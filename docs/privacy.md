# Privacy measures in ME3

What the agent does today to limit what it hears, keeps, and shares. Each item names the code that does it. This lists what is built, not a legal review. Checked Nov 3, 2026.

## Audio

- **No audio is stored.** Nothing in the harness writes microphone audio to disk. The event log keeps durations and levels only: `audio_hop` (`harness/audio_hops.py`) and `echo_window` (`harness/echo_cancel.py`) say "never audio" in their code.
- **No recordings in git.** `.gitignore` excludes `*.wav`, `*.mp3`, and `*.flac`, apart from synthesised phrases in `assets/fallback_wavs/`. `bench.doctor` fails if a recording is ever tracked.
- **Test speech is synthetic.** The benches make their speech with macOS `say` in a temporary folder (`bench/interruption_test.py`, `bench/eot_sweep.py`, `bench/echo_probe.py`), and the cached phrases are generated by TTS (`harness/phrase_cache.py`).
- **Mute stops audio at the first step.** `MicGate` (`harness/addressing.py`) drops every mic frame while muted, before the VAD and before anything reaches the cloud, and clears its pre-roll buffer. Mute comes from the touch button on the face, or `kill -USR1 <pid>` in mic mode. Each change is logged as `mic_mute`.
- **The face shows when the mic is muted.** The page draws a muted face and says "Mic muted" (`harness/ui_page.html`).

## What leaves the device

- **Speech goes to the speech recognition provider only.** The mic stream goes to Deepgram Flux. The harness sets Deepgram's `mip_opt_out=True` (`harness/providers.py`), which opts out of Deepgram's model improvement programme.
- **Text, not audio, goes to the LLM and TTS.** Anthropic receives the transcript and the conversation, and Cartesia receives the reply text.
- **Keys stay with the harness.** Keys come from `.env`, which git ignores, and are never logged. Task servers start with every `*_API_KEY` removed from their environment, except Tavily for the search server (`harness/mcp_tools.py`).
- **Messages and calls are mocks by default.** `comms` only sends for real with `ME3_TOOL_STAGES=comms=bridge`, after a spoken read-back of the real arguments and a yes (ADR-024). Contacts live in `data/contacts.yaml`, which git ignores.
- **The web fetch tool refuses private addresses**, so a page cannot steer it at devices on the local network (`servers/tasks/knowledge/server.py`).

## The screen

- **The face stays on this machine.** The UI binds to `127.0.0.1` in both profiles (`configs/mac.yaml`, `configs/pi.yaml`), and the mute and player routes refuse requests from other sites (`harness/ui.py`).
- **The screen shows the last thing heard and said.** Anyone in the room can read those captions, so that is worth mentioning before a demo.

## What is kept locally

These stay on the machine and are excluded from git (`logs/` and `data/` in `.gitignore`):

- `logs/events-*.jsonl`: one line per event, including transcripts, reply text, and tool arguments and results. No audio.
- `data/`: notes (`notes.db`), the workspace and its `.versions`, the cost ledger, mock device state, and per-server tool call logs.
- `.env`: keys and the Spotify refresh token.

Delete `logs/` and `data/` to remove what the agent has kept.

## Listening without a wake word

Addressing (ADR-016) is off by default in both profiles, so the agent treats everything it hears as meant for it. When addressing is on, a loudness gate keeps quiet room sound from reaching the cloud, and `require_wake_after_idle` can bring back a wake phrase.
